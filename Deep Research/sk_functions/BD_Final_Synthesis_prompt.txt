# Instructions
Create a concise JSON report with stable existing fields and strict phase-based optional fields.

## Required synthesis behavior
1. Preserve existing report contract fields:
   - `trigger_summary`, `executive_summary`, `top_opportunities`, `signals_detected`, `recommended_actions`, `confidence_note`.
2. Also produce optional phase fields:
   - `phase2_headline`
   - `phase2_signal_evidence`
   - `phase2_footnotes`
   - `phase3_opportunities`
   - `phase_sources`
   - `layout_version` = `fs_evidence_locked_v1` when phase fields are populated.
3. `executive_summary` must remain a single string containing exactly these three titled blocks:
   - `Deep Research Findings`
   - `Credentials Agent Findings`
   - `Combined Report & Action Items`
   - Each block should start with one concise takeaway sentence, followed by 2-4 tight bullets.
   - Write for readout-slide consumption: high signal density, minimal filler, evidence-locked language.
4. For phase fields:
   - Include only evidence from `confirmed_signals_json`.
   - `phase2_headline` must include a governing-headline style sentence that states the primary governance/risk interpretation.
   - `phase2_signal_evidence` entries must use statuses exactly: `Confirmed`, `Insufficient`, or `Rejected`.
   - For `Confirmed` entries, include short evidence quote and source URL, and write `analysis` as 2-4 concise factual sentences (not a one-liner).
   - Keep footnotes concise and link-backed.
   - `phase2_footnotes` should use structured lines that include: verbatim quote, source title, canonical URL, and evidentiary linkage.
   - `phase3_opportunities` should align to `phase3_candidates_json`; do not fabricate additional opportunities.
   - `phase3_opportunities` should use richer business language while staying evidence-locked.
5. Timeline guardrails:
   - Recommended actions must be present/future relative to current date.
   - Avoid stale past-year/past-quarter execution targets.
6. Preserve user constraints from prompt context unless contradicted by evidence.
7. Use credentials semantics accurately:
   - `Matched`, `No Match`, `Lookup Failed`.
8. If lookups were skipped (`lookups_executed_count` = 0), describe skip reason accurately.
9. For every `top_opportunities` entry, preserve the source `opportunity_id` whenever one is available in `opportunities_json`.
10. Do not fabricate opportunities, credentials, or sources.
11. Keep total output concise (prefer <= 900 words represented across JSON strings/lists).
12. In `executive_summary`, inside `Credentials Agent Findings`, include:
   - lookup status counts (Lookups executed, Matched, No Match), and
   - a short "Top matched credentials by opportunity" line for validated opportunities when matches exist.
13. Keep executive-summary wording action-oriented and factual. If lookup failures exist, state them plainly without exaggerated language.
14. Do not duplicate credentials count lines. Include each metric line once.
